## 구성 요소별 기여 (최종 모델 · 학습 5,363문장 · fp32)

②③만 쓸 때는 기준값 0.5. 스태킹은 검증셋(학습 데이터에서 뗀 15%)으로 가중치 · 기준값을 맞추고, 키워드 · kNN만으로는 위협 · 긴급이 되지 않게 바닥값을 둔 것.

| 구성 | 거친 표현 F1 | 과잉 가림률 | 위협 재현율 | 긴급 재현율 | 일반 오경보 /10 |
|---|---|---|---|---|---|
| ① 키워드만 | 0.636 | 0.0 | 0.5 | 0.8 | 0 |
| 이전 앱 (kor_unsmile + 키워드) | 0.83 | 0.033 | 0.5 | 0.8 | 0 |
| ② BERT만 | 0.983 | 0.0 | 0.9 | 0.8 | 0 |
| ③ kNN만 | 1.0 | 0.0 | 1.0 | 0.8 | 0 |
| ②+③ 평균 | 1.0 | 0.0 | 1.0 | 0.8 | 0 |
| ①+②+③ 스태킹 (지금 앱) | 0.983 | 0.0 | 0.9 | 0.8 | 0 |

- 가장 큰 변화는 키워드 → BERT (거친 표현 F1 0.64 → 0.98, 위협 재현율 0.5 → 0.9).
- kNN을 더하면 거친 표현 · 위협이 더 오른다(1.0). 스태킹은 바닥값 때문에 로컬 긴급 재현율이 0.8로 보수적 — 일반 오경보 0을 지키는 대신이고, 앱에서는 API가 한 번 더 봐서 긴급 1.00 (`results.md`).
- 평가셋이 작아 한 문장 차이로 순서가 바뀐다. 시험 문제 300개(팀원 작성)로 다시 재야 한다.
