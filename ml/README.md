# 쿠션톡 AI 판단기 (ml/)

거친 표현 · 위협 · 긴급을 **서버 안에서** 판단하는 로컬 모델. API LLM은 요약 · 순한 문장 쓰기만 맡고, 분류는 한 번 더 보는 안전망이다.

## 구조

```
구절마다 ─┬─ ① 키워드 규칙      (정밀도 높은 안전망)
          ├─ ② BERT 분류기      (kor_unsmile을 교사 LLM 라벨로 증류 학습)
          └─ ③ 의미 검색 kNN    (②의 문장 벡터로 학습 문장 뱅크에서 가장 비슷한 7개 투표)
                 ↓
          ④ 스태킹 (라벨마다 로지스틱 회귀) → rough · threat · urgent
```

- 이웃한 두 구절을 이은 문장도 한 번 더 본다 (“집에 안 왔어요. 연락이 안 돼요.”) — 분류에만 쓰고 가림에는 안 쓴다.
- kNN 이웃의 유형으로 긴급 종류(학폭 · 학대 · 안전)와 위협 이유(“찾아가겠다는 표현과 비슷한 문장”)를 붙인다.
- 뜻이 하나뿐인 욕설(STRONG)은 판단기와 상관없이 가린다. 한글이 거의 없는 구절(이모티콘 · 영어 · 코드)은 키워드로만 본다.
- `ml/models/judge`가 없거나 깨지면 예전 방식(kor_unsmile + 키워드)으로 돌아간다. 앱은 멈추지 않는다.

## 다시 만들기 (레포 루트에서)

| 순서 | 명령 | 하는 일 · 시간 |
|---|---|---|
| 1 | `backend/.venv/Scripts/python ml/gen_data.py` | 교사 LLM이 유형별 문장을 쓰고, 따로 다시 라벨 → 두 번 다 맞은 것만 `ml/data/train.json` (API 10분) |
| 1′ | `… gen_data.py --add 유형:호출수 …` · `--short` | 부족한 유형만 더 만들어 덧붙임 |
| 2 | `backend/.venv/Scripts/python ml/train.py` | 파인튜닝 4에폭 + kNN 뱅크 + 스태킹 → `ml/models/judge` (CPU 약 50분 · Colab T4 약 3분: `ml/colab_train.ipynb`) |
| 2″ | `… ml/experiments.py` | 구성 요소별 기여 · 학습 곡선 → `experiments.md` |
| 2′ | `… train.py --stack-only` | BERT는 그대로, 스태킹 · 기준값만 다시 (1분) |
| 3 | `backend/.venv/Scripts/python ml/evaluate.py` | 평가셋으로 이전 앱과 비교 → `results.md` |
| 4 | `backend/.venv/Scripts/python ml/stress_test.py` | 어려운 문장 · 이상한 입력 · 부품 고장 · 동시 요청 → `stress_results.md` |
| 5 | `backend/.venv/Scripts/python ml/export_feedback.py` | 교사 피드백 → 라벨 붙일 구절 큐 `ml/data/feedback_queue.json` |

모델 파일(약 440MB)은 git에 올리지 않는다. 팀원은 2번을 돌리거나 공유 드라이브에서 `ml/models/judge`를 받는다.

## 데이터 (`ml/data/`)

- `train.json` — 교사 LLM(충남대 AI 포털 claude-haiku-5-5)이 만들고 다시 라벨을 붙여 **두 번 다 맞은** 문장. 실제 학부모 메시지 아님. 사람 검수 전.
- `short.json` — 짧은 긴급 · 위협 문장. 처음 데이터는 긴급 문장이 길고(중앙값 64자) 함정 문장이 짧아 모델이 “짧으면 평범”을 배웠다.
- `claude.json` · `claude_F.json` · `claude_G.json` — Claude Sonnet 서브 에이전트가 만든 3,810문장(G는 여러 문장 메시지). 라벨을 지우고 섞은 문장에 다른 에이전트가 다시 라벨을 붙여 일치한 것만 (일치율 99% — 같은 모델 계열이라 높게 나왔을 수 있다).
- `review/` — 사람 검수표(1,000문장 · 두 사람) · 시험 문제 양식. `python ml/review.py score`로 κ 계산 → `reviewed.json`(가장 우선)
- `hand.json` — 교사 LLM이 **생성을 거절한** 두 유형(신체 위해 암시 · 신상 공개 위협)을 직접 쓴 19문장. 이 두 유형은 데이터가 얇다.
- 평가셋(`eval_set.json`)과 글자 3-gram 자카드 0.5를 넘게 비슷한 문장은 생성 단계에서 뺐다. 평가셋은 학습 · 기준값 고르기에 한 번도 쓰지 않는다.

## 결과 (11.05 · 최종 모델 · 학습 6,298문장 · Colab T4)

### 큰 합성 시험셋 964개 (`results_big.md` · 학습에 안 씀 · 괄호는 95% 신뢰구간)

| 지표 | 이전 앱 (kor_unsmile + 키워드 + API) | 지금 앱 (증류 판단기 + API) |
|---|---|---|
| 거친 표현 F1 (문장 478) | 0.49 | **0.97** |
| 거친 표현 재현율 | 0.33 (0.28~0.40) | **0.96 (0.93~0.98)** |
| 과잉 가림률 | 0.04 | 0.03 |
| 긴급 재현율 (메시지 146) | 0.91 | **0.99 (0.95~1.00)** |
| 위협 재현율 (메시지 145) | 0.39 ~ 0.85 ※ | **0.94 (0.89~0.97)** |
| 일반 오경보율 (메시지 195) | 0.04 ~ 0.05 | 0.07 (0.04~0.12) |
| 메시지 정확도 | 0.77 ~ 0.92 ※ | **0.95 (0.93~0.97)** |
| API 없이 로컬만 정확도 | 0.46 | **0.92** |

※ 이전 앱은 위협 판단을 API에 기대서, 같은 시험을 두 번 돌렸을 때 위협 재현율이 0.85와 0.39로 크게 흔들렸다 (API 응답 지연 · 변동). 지금 앱은 로컬이 먼저 판단해 흔들림이 적다.

### 작은 평가셋 90개 (`results.md`) · 시뮬레이션 (`stress_results.md`)

거친 표현 F1 0.83 → 0.97, API까지 긴급 · 위협 · 일반 모두 1.00. 어려운 문장 23개 중 22개 (이전 7개). 메시지 한 통 로컬 판단 중앙값 약 50ms.

작은 평가셋은 문항이 적어(분류별 10개) 한 문장이 0.10을 움직인다 — 발표에는 큰 시험셋 숫자를 쓴다. 단, 큰 시험셋도 Claude가 만든 합성 문장이라 실제 학부모 메시지에서는 더 낮을 수 있다.

## 시뮬레이션으로 찾아 고친 것 (11.04)

| 찾은 문제 | 원인 | 고친 것 |
|---|---|---|
| 평범한 문장 60%를 가림 | LLM이 쓴 평범한 문장은 “선생님 안녕하세요 ○○ 엄마예요”로 길게 시작 → “짧고 무뚝뚝하면 거침”이라는 지름길 | 평범한 문장을 구절로도 잘라 학습 (앱도 구절 단위로 판단) |
| 긴급 재현율 0.40 | 긴급은 길고 함정 문장은 짧음 → “짧으면 평범” | 짧은 긴급 · 위협 510문장 추가 |
| “고소한 냄새” · “찾아가는 음악회” · “각오를 다지고”가 위협 | 기준값을 “재현율 0.95 이상”으로 골라 0.02까지 내려감 → 키워드 하나만으로 위협 | 오경보율 상한 안에서 고르고, 키워드 하나만으로는 넘지 못하게 바닥값 |
| 합성 검증셋에서 고른 기준값이 실제 문장에서 흔들림 | 검증셋이 쉬워 점수가 0.02 아니면 0.9 — 같은 성적 구간의 끝을 골랐음 | 같은 성적 구간의 가운데(로짓 기준) |
| `<script>` · 이모티콘 · 아주 긴 글이 긴급 · 위협 | 학습한 적 없는 입력, 긴 글을 통째로 넣음 | 한글 2자 미만은 키워드로만, 통째 대신 이웃 두 구절 |
| 빈 글에 1.4초 | 빈 입력에서 쓰지도 않는 예전 모델을 불러옴 | 빈 입력은 바로 반환 |
| “한심하네요” · “개.념.없.네”를 놓침 | 함정 데이터 때문에 키워드를 덜 믿게 배움 · 점으로 끊어 씀 | 뜻이 하나뿐인 욕설은 항상 가림 · 키워드 비교에서 점 · 기호 무시 |
| API가 끊기면 4.2초 기다림 | 연결 거부도 한 번 더 물음 | 연결 자체가 안 되면 바로 로컬 결과 |
| 큰 시험셋에서 일반 메시지 11%를 긴급 · 위협으로 오경보 | 학습 데이터가 거의 한 문장 — “다쳤는데 괜찮아요” 같은 뒤집기 · 여러 문장 불만을 못 배움 | 여러 문장 메시지 935개(뒤집기 · 거친 불만 + 요청 · 일상 · 균형용 긴급 · 위협) → 0.07 |
| 시연 문장 “짝이랑 안 맞아서 매일 울면서 와요”가 긴급 | 아이가 속상하지만 위험은 아닌 문장이 데이터에 없음 · 교사 탓하는 구절과 이은 묶음이 학습에 없던 문장이 됨 | `일반_아이속상` · `비꼼_자격` 추가 · 거친 구절이 낀 묶음은 긴급 근거에서 뺌 |
| 부호 없이 930자인 글이 한 구절 | 128토큰에서 잘려 엉뚱한 판단 · 느림 | 80자 넘는 구절은 띄어쓰기에서 자름 · 묶음은 12개까지 |
| INT8 양자화가 배치에 따라 점수를 바꿈 (같은 구절 긴급 0.15 ↔ 0.60) · 이 CPU에선 오히려 느림 (56 vs 40ms) | 동적 양자화는 배치 전체(패딩 포함)로 눈금을 잡는다 | fp32로 (INT8은 `CUSHION_INT8=on` 비교용) |
| 욕설을 위협으로 봄 (“씨 발 장난하세요?”) | 위협 데이터엔 욕이 많고, 욕만 있는 문장은 29개뿐 | 욕설 · 반말 400문장(위협 아님) 추가 |
| API가 응답을 조금씩 흘려보내면 끝없이 기다림 | urlopen 시간 제한은 '한 번 읽을 때'만 잼 | 응답 전체에 시간 상한 (최대 약 12초 뒤 로컬 결과) |

## 남은 한계

- 학습 데이터가 전부 LLM이 만든 문장이다. 사람 검수 · 실제 말투 데이터(교권 메시지)가 들어가야 숫자를 믿을 수 있다.
- 평가셋 90개는 작다. 문장 하나가 재현율 0.10을 움직인다.
- 신체 위해 암시 · 신상 공개 위협은 직접 쓴 19문장뿐이라, 이 둘은 API 안전망에 기대는 비중이 크다.
- 아직 틀리는 것: “넘어질 뻔했는데 괜찮대요” → 긴급(부정 표현), “선생님 가족분들도 이 일 아시나요?” → 위협을 놓침.
- 한국어만 본다. 영어 · 외국어 메시지는 키워드 규칙과 API만으로 판단된다.
