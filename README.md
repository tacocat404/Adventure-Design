# 쿠션톡 (CushionTalk)

**학부모 메시지를 AI가 먼저 읽고, 교사에게는 요청만 전해 주는 학교 소통 앱**

공격적인 표현은 가리고, 요청은 하나도 빼지 않아요. 위협은 교사 혼자가 아니라 학교가 받아요.

![쿠션톡 화면 · 교사 메시지함, 메시지 상세, 학부모 보내기 전 경고](docs/images/screens_e2.png)

> 지금은 **앱 초안** 단계예요. 위 화면은 확정 디자인 시안(E2)이고, 앱 초안도 이 시안대로 돌아가요. AI는 아직 키워드 규칙이라 학습 모델로 바꿀 차례예요. ([진행 상황](#진행-상황) · [실행하기](#실행하기))

---

## 왜 만드나

2026년 3월부터 학부모 연락이 학교 공식 플랫폼으로 모였지만, 메시지는 걸러지지 않고 그대로 교사에게 가요. 교사는 요청을 알기 위해 모욕적인 말까지 끝까지 읽어야 하고, 이런 일이 쌓이면 직무 스트레스와 교권 침해로 이어져요.

| 지금 | 쿠션톡에서는 |
|---|---|
| 메시지를 걸러 주는 장치가 없다 | **AI 완충** — AI가 먼저 읽고 공격적인 표현을 가린 **요청 요약**만 보여 줘요 |
| 수신을 끄면 다 막히고, 켜면 다 받는다 | **표현만 거름** — 요청은 그대로. 교사는 원하면 언제든 [원문 보기] |
| 위협을 교사 혼자 감당한다 | **위협 자동 이관** — 관리자(교감 · 민원대응팀)에게 넘기고 원문을 시간과 함께 보존 |
| 보내는 쪽에 멈출 계기가 없다 | **보내기 전 경고** — “이 표현은 교권 침해로 기록될 수 있어요” + 순한 문장 제안 |
| 반 단톡방을 만들면 개인 메신저가 노출된다 | **앱 안 반 톡방** — 참여 코드로 학생을 부르고, 교사 개인 계정은 보이지 않아요 |

## 메시지 한 통이 가는 길

```mermaid
flowchart LR
    P["학부모<br/>메시지 쓰기"] --> C{"거친 표현?"}
    C -- "예" --> W["경고 · 순한 문장 제안"]
    W --> S
    C -- "아니오" --> S[("원문 저장<br/>받은 시간 · 지문")]
    S --> AI["AI 분석"]
    AI -- "긴급<br/>학교폭력 · 아동학대 · 안전" --> U["교사: 원문 그대로 맨 위"]
    AI -- "일반" --> N["교사: 요청 요약<br/>거친 표현은 스티커로 가림"]
    AI -- "위협<br/>애매해도 위협" --> T["관리자: 증거와 함께 대응"]
    T -. "담임도 요약을 받음" .-> N
    AI -. "분석 실패" .-> F["교사: 원문 접은 채 전달"]
```

- **저장이 분석보다 먼저**예요. 원문과 서버 시간을 먼저 남기고, 원문은 고치거나 지울 수 없어요 (SHA-256 지문으로 확인).
- 긴급 메시지는 요약하면 대응이 늦어질 수 있어서 **가리지 않고 원문 그대로** 보여 줘요.
- 교사 답장, 반 톡방 메시지는 AI를 거치지 않아요.

| **학생** | 참여 코드 + 이름 (로그인 없음) | 반 단체 톡방에서 담임 · 친구들과 대화 |

## 실행하기

**Windows는 레포 맨 위의 `실행.bat`을 더블클릭하면 끝이에요.** 처음이면 설치까지 알아서 하고, 창 두 개가 뜬 뒤 브라우저가 열려요. 두 창은 끄지 말고 그대로 두세요.

> **왜 창이 두 개예요? — 식당으로 생각하면 돼요.**
> - **백엔드 = 주방**: 주문(메시지)을 받아 요리(AI 분석, 저장)를 해요. 손님 눈에는 안 보여요.
> - **프론트 = 홀**: 손님(학부모 · 교사)이 보는 화면이에요.
>
> 주방과 홀은 하는 일이 달라서 따로 문을 열어요. 홀이 받은 주문을 주방에 넘기는데(`/api`), 둘 중 하나라도 닫혀 있으면 식당이 안 돌아가요. 그래서 창이 두 개예요.

직접 켜려면 (macOS · Linux 포함) 처음 한 번만 설치해요.

```bash
cd backend && python -m venv .venv && .venv/Scripts/python -m pip install -r requirements.txt
```

```bash
cd frontend && npm install
```

서버 두 개를 각각 켜요. 브라우저는 http://localhost:5173 으로 열어요 (휴대폰 폭으로 보면 좋아요).

```bash
cd backend && .venv/Scripts/python -m uvicorn app.api.main:app --reload
```

```bash
cd frontend && npm run dev
```

- 처음 켜면 `backend/cushion.db`가 생기고 예시 데이터가 들어가요. 처음부터 다시 하려면 이 파일을 지우면 돼요.
- 예시 계정은 비밀번호가 모두 `pass1234`예요: 교사 `teacher1`(김하늘, 3학년 2반) · 관리자 `admin1` · 학부모 `parent1`(민서) · `parent2`(하윤) · `parent3`(서연) · `parent4`(서준) · `parent5`(하은) · `parent6`(지호) · 학생 `student1`(정서준) · `student2`(오하은) · `student3`(강지호) · `student4`(박민서) · `student5`(최하윤) · `student6`(한서연). 처음 켜면 시연용 더미 데이터(긴급 · 위협 · 거친 표현 가림 메시지, 답장, 출결, 체험학습 승인/반려, 알림장 확인 현황, 상담 예약, 설문 결과, 반 톡방 대화, 가입 대기)가 한 번 들어가요. 끄려면 `CUSHION_RICH_DEMO=off`.
- **로그인은 소셜 로그인이에요.** 카카오 · 네이버 · 구글 개발자 앱 키가 오기 전에는 소셜 버튼이 이름만 넣는 **데모 로그인**으로 돌아요 (`backend/.env`의 `CUSHION_DEMO_LOGIN=on`이 기본). 선생님 · 교직원으로 가입하면 관리자가 승인해야 써요: 관리자 `admin1`로 들어가 “가입 승인”에서 승인해요. 시작 화면의 “개발용 테스트 계정으로 들어가기”로 아래 예시 계정에 바로 들어갈 수도 있어요.
- DB 모양이 바뀌었어요(소셜 계정 칸). 이전에 켠 적이 있으면 `backend/cushion.db`를 지우고 다시 켜 주세요.
- 학생은 교사 화면 → 반 톡방 → 참여 코드로 들어가요.
- API 문서는 서버를 켠 뒤 http://localhost:8000/docs 에서 볼 수 있어요.
- **AI까지 켜려면** (선택, 안 하면 키워드 버전으로 돌아요)
  1. `backend/.env.example`을 `backend/.env`로 복사하고 `CNU_API_KEY=` 뒤에 충남대 AI 포털 키를 넣어요. `.env`는 레포에 올라가지 않아요.
  2. 로컬 판단 모델 설치(약 2GB, 처음 한 번): `cd backend && .venv/Scripts/python -m pip install -r requirements-ai.txt --extra-index-url https://download.pytorch.org/whl/cpu`
  3. 서버를 다시 켜요. 처음엔 모델을 내려받느라 1분쯤 걸려요.
- 흐름 검사: `cd backend && .venv/Scripts/python test_flow.py` (AI는 끄고 흐름만) · AI 검사: `.venv/Scripts/python app/ai/analyzer.py` · AI 평가: 레포 맨 위에서 `backend/.venv/Scripts/python ml/evaluate.py` → `ml/results.md`
- macOS · Linux에서는 `.venv/Scripts/python` 대신 `.venv/bin/python`을 써요.
