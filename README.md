# 쿠션톡 (CushionTalk)

학부모가 보낸 메시지를 **AI가 먼저 읽고**, 공격적 표현은 가리고 **요청만** 교사에게 보여 주는 앱.

기술 스택: React (모바일 화면 기준 웹) · Python FastAPI · SQLite · LLM

## 폴더 구조

```
Adventure-Design/
├─ docs/                # 목차(index.html)와 기획 · 흐름 · 화면 · 시안 · 데이터 · API 문서
│  └─ 보관/             # 지난 문서 (10.13 앱정의서 · 유저 플로우)
├─ git-practice/        # 브랜치·커밋·푸시·풀 연습용 (연습 끝나면 삭제)
├─ backend/
│  └─ app/
│     ├─ ai/            # AI 분석 (이름 가림 → 키워드 필터 → LLM → 긴급/위협 분기) · API 명세 05절
│     ├─ api/           # API (로그인, 메시지, 보내기 전 검사, 관리자, 반 톡방) · API 명세 03절
│     └─ db/            # schema.sql (DB 설계 07절 생성문)
└─ frontend/
   └─ src/
      ├─ pages/         # 화면 (로그인 · 학부모 · 교사 · 관리자 · 반 톡방) · 와이어프레임 26장
      └─ components/    # 공통 부품 (배지, 버튼, 시트, 쿠션이) · 컴포넌트 명세
```

## 역할

| 역할 | 담당 |
|---|---|
| 팀장 | `docs/`, PR 리뷰, 일정 |
| 풀스택 | 관리자 화면 (프론트+백엔드), 프론트↔백엔드 연결 |
| 백엔드 A | `backend/app/ai/` |
| 백엔드 B | `backend/app/api/`, DB |
| 프론트 A | 학부모 화면, `components/` |
| 프론트 B | 교사 메시지함·상세 |

로그인 · 가입(G)과 반 톡방(E · F) 화면 담당은 Todo 분담표에서 정해요.

## 브랜치 · 커밋 규칙

자세한 건 [Git · GitHub 규칙](docs/바이브코딩%20협업표/Git_GitHub_규칙.md)을 따라요.

- `main`에 직접 push 금지, PR로만 머지
- 브랜치 이름: `종류/산출물ID-짧은-설명` (예: `feat/T1-MJ-login-page`, 분담표에 없는 작은 수정은 `docs/etc-fix-typo`)
- 커밋 메시지: `종류: 무엇을 했는지` (예: `docs: API 명세에 오류 코드 추가`)
