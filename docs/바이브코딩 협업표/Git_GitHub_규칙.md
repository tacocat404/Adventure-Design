# {팀 이름} Git·GitHub 규칙

## 0. 레포

레포 링크: 

## 1. 브랜치 규칙

| 브랜치 | 역할 |
| --- | --- |
| `main` | 항상 실행되는 상태를 유지한다. 리뷰를 통과한 코드만 들어온다. 직접 올리지(push) 않고 PR로만 합친다. `git push --force`는 쓰지 않는다 |
| 작업 브랜치 | 분담표의 산출물 하나당 하나. 작업이 끝나 합치면 지운다 |

**이름 짓는 법:** `종류/산출물ID-짧은-설명`

| 종류 | 언제 | 예 |
| --- | --- | --- |
| `feat` | 새 기능 | `feat/T1-MJ-login-page` |
| `fix` | 버그 수정 | `fix/T2-YS-upload-timeout` |
| `docs` | 문서만 수정 | `docs/T1-HS-api-spec` |
| `refactor` | 동작은 그대로, 코드 구조만 정리 | `refactor/T3-SY-split-scorer` |
| `test` | 테스트 추가·수정 | `test/T2-YS-validator-cases` |
| `chore` | 설정, 패키지, 빌드 등 기타 | `chore/T1-MJ-update-deps` |

산출물 ID는 분담표에 적힌 그대로 쓰고, 설명은 영어 소문자와 하이픈(`-`)으로 짧게 쓴다. 한글과 띄어쓰기는 쓰지 않는다. 분담표에 없는 작은 수정(오타, 설정 등)은 산출물 ID 대신 `etc`를 쓴다(예: `docs/etc-fix-typo`).

**브랜치는 짧게 유지한다.** 며칠씩 혼자 끌고 가면 main과 차이가 커져 합칠 때 충돌이 많아진다. 작업이 길어지면 분담표에서 산출물을 쪼갠다.

## 2. 커밋 규칙

**메시지 형식:** `종류: 무엇을 했는지`

```text
feat: 로그인 화면 추가
fix: 500MB 넘는 ZIP 업로드 시 서버가 멈추는 문제 수정
docs: API 명세에 제출 상태 값 추가
```

- 종류는 1번 브랜치 종류와 같은 6가지를 쓴다.
- 설명은 한국어로 쓰고, 무엇을 바꿨는지 한 줄로 적는다. 이유가 필요하면 한 줄 띄우고 본문에 적는다.
- 커밋 하나에는 한 가지 일만 담는다. "로그인 추가 + 버그 수정 + 오타 수정"을 한 커밋에 넣지 않는다.

**올리면 안 되는 것**

| 종류 | 예 | 대신 |
| --- | --- | --- |
| 비밀 정보 | 비밀번호, API 키, 토큰, `.env` 파일 | `.env.example`에 키 이름만 적어 올린다 |
| 큰 파일 | 데이터셋, 모델 가중치, 압축 파일 | 공유 드라이브 등 별도 위치에 두고 경로만 적는다 |
| 자동 생성 파일 | `node_modules/`, `__pycache__/`, `.venv/`, 빌드 결과물 | `.gitignore`에 등록한다 |
| 개인 설정 | `.vscode/`, `.idea/`, OS 임시 파일 | `.gitignore`에 등록한다 |

커밋하기 전에 `git status`로 올라갈 파일 목록을 확인한다.

## 3. PR 규칙

**제목:** `[산출물 ID] 종류: 무엇을 했는지`. 예: `[T1-MJ] feat: 로그인 화면 추가`. 합칠 때 이 제목이 main의 커밋 메시지가 된다.

**본문:** 레포에 `.github/pull_request_template.md`를 두면 PR을 열 때 자동으로 나온다.

```markdown
## 무엇을 바꿨나

## 왜 바꿨나

## 어떻게 확인했나
<!-- 직접 실행한 명령, 확인한 화면, 테스트 결과 -->

## 산출물
<!-- 분담표의 산출물 ID와 Todo 번호. 예: T1-MJ (Todo #1) -->

## 버그 수정이라면
<!-- 재현 방법, 실제 결과, 기대 결과. 아니면 지운다 -->

## 체크
- [ ] 비밀 정보·큰 파일이 포함되지 않았다
- [ ] 계약(API 명세, 데이터 형식)을 바꿨다면 관련 팀원에게 알렸다
```

- PR 하나는 분담표의 산출물 하나에 대응한다.
- PR을 올리면 리뷰어에게 PR 링크를 보낸다.
- 바뀐 줄이 400줄을 넘으면 리뷰하기 어렵다. 가능하면 나눈다.
- 아직 작업 중이면 Draft PR로 올려 진행 상황을 공유할 수 있다.
