# 문서 디자인 형식서

바이브코딩 협업표의 문서(서비스 정의서, 유저 플로우, Todo 분담표 등)를 **HTML 디자인 자료**로 뽑을 때 따르는 규칙이다. 누가, 어떤 AI로 만들어도 같은 모양이 나오게 하는 것이 목적이다.

| 파일 | 역할 |
|---|---|
| `디자인_형식서.md` (이 문서) | 색 · 글자 · 배치 · 컴포넌트 · 다이어그램 규칙 |
| `디자인_컴포넌트.html` | 컴포넌트 견본과 복사용 코드, FlowKit(다이어그램 렌더러), 시작 뼈대 |
| `../유저플로우_쿠션톡_261015.html` | 이 형식으로 만든 실제 예 (참고 구현) |

## 0. AI에게 맡길 때

HTML을 AI로 뽑을 때는 프롬프트에 아래 문장을 그대로 넣는다.

```text
문서/바이브코딩 협업표/디자인_형식서.md 규칙을 따라 HTML을 만들어 줘.
디자인_컴포넌트.html의 "시작 뼈대"를 복사해서 시작하고, 컴포넌트는 그 파일에 있는 것만 써.
유저 플로우 다이어그램은 FlowKit 데이터 형식으로 그리고, 다 그린 뒤 FlowKit.check() 결과가 빈 배열인지 확인해.
```

## 1. 기본 원칙

1. **파일 하나:** HTML 한 파일에 스타일과 스크립트를 모두 넣는다. 브라우저로 열기만 하면 보여야 한다.
2. **불러오는 것은 두 개만:** Tailwind CDN, Pretendard 글꼴. 다이어그램은 외부 라이브러리 없이 FlowKit(SVG)으로 그린다.
3. **밝은 종이 바탕:** 베이지 바탕 위에 흰 카드를 올린다. 어두운 바탕, 보라·파랑 그라데이션, 네온 효과는 쓰지 않는다.
4. **모양이 먼저, 색은 그다음:** 다이어그램은 블록 모양만 보고도 뜻이 읽혀야 한다. 색은 모양을 돕는 역할이다.
5. **이모지 금지:** 아이콘이 필요하면 SVG 도형이나 글자로 대신한다.
6. **한국어 줄바꿈:** 한글 글 덩어리에는 `keep` 클래스(`word-break: keep-all`)를 붙인다.
7. **모바일:** 페이지가 가로로 넘치면 안 된다. 넓은 다이어그램과 표만 자기 칸 안에서 좌우로 민다.

## 3. 페이지 뼈대

모든 HTML 자료는 이 순서를 따른다.

```text
상단 바 (TopBar)            서비스 이름 + 섹션 바로가기, 위에 고정
페이지 헤더 (PageHeader)     아이브로 · 큰 제목 · 오른쪽 요약 · 굵은 검정 가로줄
섹션 01 … 0N (SectionTitle) "01  제목  보조 설명" 형식으로 번호를 붙인다
푸터 (Footer)               근거 문서 · 양식 파일 이름
```

## 4. 컴포넌트

견본과 복사용 코드는 `디자인_컴포넌트.html`에 있다. 여기 없는 컴포넌트를 새로 만들어야 하면, 먼저 이 표에 추가하고 컴포넌트 파일에 견본을 올린다.

| 컴포넌트 | 생김새 | 쓰는 곳 |
|---|---|---|
| **TopBar** | 반투명 종이색 바, 왼쪽 서비스 이름, 오른쪽 섹션 링크 | 모든 페이지 |
| **PageHeader** | 아이브로 + 큰 제목(두 줄) + 오른쪽 정렬 요약 + `border-b-2 border-ink` | 모든 페이지 |
| **SectionTitle** | `01` 번호(아이브로) + 굵은 제목 + 회색 보조 설명 | 모든 섹션 |
| **LegendCard** | 흰 카드, 왼쪽 연한 색 타일 안에 도형, 오른쪽 이름 · 설명 · 예시 칩 | 블록 범례, 핵심 개념 소개 |
| **Chip** | 회색 바탕 작은 글자 상자 | 화면 번호, 예시, 태그 |
| **StatusBadge** | 블록 색을 빌린 상태 상자 (대기 · 진행 · 완료 · 보류 · 임시) | 분담표 상태, 화면 상태 |
| **PanelCard** | 흰 큰 카드 (`rounded-[28px]`) | 지도, 다이어그램, 긴 내용 |
| **FlowCard** | PanelCard 안: 위쪽 왼편 플로우 배지 · 누가 · 무엇을 · 목표 · 화면 칩, 오른편 메모 목록, 아래 다이어그램 | 유저 플로우 한 개 |
| **MemoList** | 회색 점 목록, (미정)은 주황 굵은 글자 | FlowCard 오른편, 보충 설명 |
| **FlowCanvas** | FlowKit으로 그린 SVG, 좁으면 좌우 스크롤 | 유저 플로우, 서비스 흐름 |
| **MapCanvas** | FlowKit `card` 블록 + 연결점 배지 화살표 | 전체 지도 |
| **RuleColumns** | 위에 굵은 검정 줄이 있는 칸 3개씩 (아이브로 · 굵은 제목 · 설명) | 원칙, 해결 방안, 기대 효과 |
| **DataTable** | 흰 카드 안 표, 머리글 아래 `border-b-2 border-ink` | 대상 사용자, 화면 번호, 분담표 |
| **OpenList** | 위에 굵은 검정 줄, 항목마다 플로우 배지 + 질문 | 아직 정하지 않은 것 |
| **Footer** | 가는 줄 위에 근거 문서 · 양식 이름 | 모든 페이지 |

### 4-1. 문서 종류별로 쓰는 컴포넌트

| 문서 (양식) | 섹션 → 컴포넌트 |
|---|---|
| 서비스 정의서 (`서비스정의서_양식.md`) | 최종 목표 → PageHeader 요약 · 대상 사용자 → DataTable · 문제 상황 → PanelCard 본문 · 원인 → RuleColumns(번호를 아이브로로) · 해결 방안 → DataTable 또는 RuleColumns · 기대 효과 → RuleColumns |
| 유저 플로우 (`유저플로우_양식.md`) | 블록 정의 → LegendCard 8칸 · 전체 지도 → MapCanvas + DataTable(연결점) · 플로우 → FlowCard × N · 해결 방안 매핑 → RuleColumns · 화면 번호 → DataTable + StatusBadge · 미정 → OpenList |
| Todo 분담표 (`Todo_분담표_양식.md`) | 팀원 분류 → DataTable · Todo 한눈에 → DataTable + StatusBadge · Todo 상세 → PanelCard 안 DataTable, 공동 확인 · 완료 기준은 RuleColumns 2칸 |

## 5. 다이어그램 규칙 (FlowKit)

블록 모양과 선의 뜻은 `유저플로우_블록정의.md`를 따른다. 여기서는 HTML로 그릴 때의 규칙만 정한다.

### 5-1. 데이터 형식

```js
const FLOW = {
  W: 1500, H: 480,               // 캔버스 크기 (viewBox)
  nodes: [
    { id: 'S', t: 'start',    x: 70,  y: 110, l: '앱 실행' },
    { id: 'A', t: 'screen',   x: 245, y: 110, l: '학부모 작성', s: '6-1' },  // s = 화면 번호나 (시트)
    { id: 'I', t: 'input',    x: 455, y: 110, l: '메시지 쓰기' },
    { id: 'P', t: 'system',   x: 735, y: 110, l: '보내기 전\n표현 검사' },   // \n 으로 줄 나눔
    { id: 'Q', t: 'decision', x: 920, y: 110, l: '거친 표현\n있나?' },
    { id: 'X', t: 'conn',     x: 1430, y: 110, l: 'B' },
  ],
  edges: [
    ['S.r', 'A.l'],                              // [출발.면, 도착.면, 라벨]  면: l r t b
    ['I.r', 'P.l', '보내기 클릭'],
    { f: 'C.l', t: 'I.b', l: '직접 고치기', dash: 1, via: [[455, 420]] },  // dash = 빨간 점선, via = 꺾는 점
  ],
  memos: [
    { x: 1016, y: 260, t: '순한 문장을 하나 이상 제안' },          // a: 'start' | 'middle' | 'end'
    { x: 1026, y: 602, t: '경고 무시 기록을 보여 주나?', o: 1 },   // o = (미정)
  ],
};
FlowKit.mount('#flow-a-canvas', 'a', FLOW);
```

| 블록 `t` | 기본 크기 (가로 × 세로) | 한 줄 글자 수 |
|---|---|---|
| `start` | 116 × 48 | 6자 (넘으면 `w` 지정) |
| `screen` | 160 × 58 | 8자 + 보조 줄 |
| `input` | 176 × 52 | 8자, 넘으면 두 줄 |
| `system` | 180 × 58 | 8자 × 2줄 |
| `decision` | 150 × 96 | 5자 × 2줄, `?`로 끝남 |
| `conn` | 지름 40 | 대문자 한 글자 |
| `card` (지도) | 300 × 84 | `who`, `what`, `href` |

### 5-2. 배치

- 기본 흐름은 **왼쪽 → 오른쪽**, 첫 줄 `y = 110`. 아래 줄은 `+155 ~ +170`씩 내린다.
- 분기의 두 길 중 주된 길은 오른쪽, 다른 길은 아래로 뺀다.
- 블록 사이 간격: 라벨 없는 화살표는 25 이상, 라벨 있는 화살표는 **라벨 폭 + 10** 이상 (한 글자 약 14, 여백 18. 예: `보내기 클릭` ≈ 90).
- 선은 직각으로만 꺾는다. 블록을 가로지르면 `via`로 돌린다. 선끼리 교차하지 않게 하고, 한 블록으로 모이는 합류는 괜찮다.
- 선이 멀리 돌아가야 하면 그 자리에 **같은 글자의 연결점**을 하나 더 두고, 아래에 `교사로`처럼 행선지 메모를 단다.
- 빨간 점선은 되돌아가기 · 실패 · 예외에만 쓰고, 그 라벨도 빨간색이다.

### 5-3. 메모

- 블록 옆이나 아래에 14px 회색으로 단다. 한 줄 20자 안쪽, 두 줄까지.
- 길게 설명할 내용은 다이어그램이 아니라 FlowCard 오른편 MemoList에 쓴다.
- 아직 정하지 않은 것은 `o: 1`로 표시하고, 같은 내용을 OpenList에도 모은다.

### 5-4. 다 그린 뒤 점검

브라우저 콘솔에서 `FlowKit.check()`를 실행한다. 빈 배열 `[]`이 나와야 끝이다. 나오는 문제와 고치는 법:

| 점검 결과 | 고치는 법 |
|---|---|
| 라벨이 블록에 닿음 | 두 블록 간격을 라벨 폭 + 10 이상으로 벌린다 |
| 메모가 선 · 블록 · 라벨과 겹침 | 메모 `x, y`나 `a`(정렬)를 바꾼다 |
| 글자가 블록보다 김 | `\n`으로 줄을 나누거나 `w`를 키운다 |
| 캔버스 밖 메모 | `W, H`를 늘린다 |

## 6. 완성 전 체크리스트

- [ ] 파일 하나로 열리고, 불러오는 것은 Tailwind CDN과 Pretendard뿐이다
- [ ] 페이지 뼈대(TopBar → PageHeader → 번호 섹션 → Footer)를 따랐다
- [ ] 색은 2장의 토큰만 썼고, 같은 색을 다른 뜻으로 쓰지 않았다
- [ ] 이모지가 없고, 한글 덩어리에 `keep`이 붙어 있다
- [ ] 다이어그램이 블록 정의서의 모양을 따르고 `FlowKit.check()`가 `[]`이다
- [ ] (미정) 항목이 다이어그램 메모 · MemoList · OpenList에서 서로 맞는다
- [ ] 375px 폭에서 페이지가 가로로 넘치지 않는다
- [ ] MD 원본과 내용(블록 · 분기 · 메모)이 같다
