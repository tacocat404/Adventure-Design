# [26.10.15] 쿠션톡 서비스 정의서 (팀원용)

## 최종 목표 서비스

초등학교 교사가 학부모 메시지를 받을 때, **AI가 먼저 읽고** 공격적인 표현을 걸러 **요청 내용만** 교사에게 전달하는 서비스.

## 1. 대상 사용자

| 대상 | 대상이 서비스에서 쓰는 기능 |
|---|---|
| **교사** (초등학교 담임) — 주 사용자 | 학부모 메시지를 받는다. 걸러진 요청 요약을 보고 답장한다. 개인 메신저 없이 반별 학생 단체 톡방(예: 1-#반)을 연다. |
| **학부모** | 담임에게 메시지를 보낸다. 거친 표현을 쓰면 보내기 전에 경고를 받는다. |
| **학생** | 반별 단체 톡방(예: 1-#반)에서 담임과 소통한다. |
| **관리자** (교감·민원대응팀) | 위협 메시지를 넘겨받아 학교 차원에서 대응한다. |

## 2. 문제 상황

교사는 학부모 메시지 속 요청을 이해하려면 메시지를 끝까지 읽어야 한다. 그 과정에서 모욕적이거나 공격적인 표현까지 그대로 읽게 된다. 이런 일이 쌓이면 직무 스트레스가 되고, 교권 침해로 이어지기도 한다.

## 3. 원인

문제 상황이 생기는 이유를 나눠 적는다. 각 원인은 4번에서 해결 방안과 하나씩 짝지어진다.

1. 학교 통합 플랫폼에 걸러 주는 장치가 없다
   2026년 3월부터 학부모 연락이 학교 공식 플랫폼으로 모이게 됐다. 하지만 플랫폼에 모인 메시지는 걸러지지 않고 그대로 교사에게 전달된다.

2. 기존 앱은 다 막거나 다 받거나 둘 중 하나다
   메시지 수신을 끄면 일반 학부모의 요청까지 막히고, 켜 두면 공격적인 민원을 그대로 받는다.

3. 위협적인 메시지를 교사 혼자 감당한다
   협박이나 공격적인 메시지를 받아도 일을 키우고 싶지 않아 학교 대응 체계로 보고하기 애매하다. 그래서 교사 혼자 넘기는 분위기가 있다.

4. 보내는 쪽에 공격적인 표현을 멈출 계기가 없다
   순간적으로 흥분해 공격적인 표현을 쓰는 것도 잘못이지만, 보내기 전에 이를 막거나 다시 생각해 볼 기회가 없다.

5. 반 단체 톡방을 만들려면 개인 메신저를 써야 한다
   1-#반처럼 학생 단체 톡방을 카톡 등 개인 메신저로 만들면 교사의 개인 메신저가 학생에게 노출된다.

## 4. 해결 방안

원인 하나에 해결책 하나씩 대응한다.

| 원인 | 해결 방안 |
|---|---|
| 1. 걸러 주는 장치가 없다 | **AI 완충:** AI가 메시지를 먼저 읽고, 공격적인 표현을 가린 뒤 **요청 요약**만 교사에게 보여 준다. |
| 2. 다 막거나 다 받거나 | **내용은 그대로, 표현만 거름:** 요청은 하나도 빼지 않는다. 교사는 원하면 [원문 보기]로 언제든 원문을 볼 수 있다. |
| 3. 위협을 혼자 감당한다 | **위협 자동 이관:** 위협 메시지는 관리자에게 자동으로 넘기고, 원문을 시간과 함께 보존한다. |
| 4. 보내는 쪽에 멈출 계기가 없다 | **보내기 전 경고:** 학부모가 거친 표현을 쓰면 "이 표현은 교권 침해로 기록될 수 있어요"라고 알리고 순한 문장을 제안한다. |
| 5. 반 단체 톡방에 개인 메신저가 노출된다 | **앱 안 반 단체 톡방:** 교사가 앱 안에서 반별 학생 단체 톡방(예: 1-#반)을 만든다. 개인 메신저 계정을 공유하지 않아도 된다. |

추가로 꼭 있어야 하는 기능

- 긴급 메시지 원문 우선 표시: 학교폭력, 아동학대, 안전 관련 메시지는 걸러 요약하면 대응이 늦어질 수 있다. 원문 그대로 맨 위에 보여 준다.
- 애매한 표현은 위협으로 분류: 위협을 놓치는 것보다 한 번 더 확인하는 쪽이 안전하다.

## 5. 기대 효과

| 누구에게 | 효과 |
|---|---|
| **교사** | 공격적인 표현에 노출되지 않고 학부모가 원하는 내용만 보고 일한다. 개인 메신저를 노출하지 않고 반 학생들과 소통한다. |
| **학부모** | 원하는 내용은 그대로 전달되고, 보내기 전에 표현을 돌아볼 기회를 얻는다. |
| **학교** | 교사에 대한 위협을 교사 개인이 아니라 학교에 대한 공격으로 보고, 학교 대응 체계로 처리한다. |
