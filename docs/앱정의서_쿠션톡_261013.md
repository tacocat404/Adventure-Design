# [26.10.13] 쿠션톡 앱 정의서 (팀원용)

## 최종 목표 앱

학부모가 보낸 메세지를 **AI가 먼저 읽고**,교사에게 공격적 표현을 제거하고 **목적** 만 들어나게 하는 앱

## 1.대상 사용자

| 대상 | 대상이 앱에서 쓰는 기능 |
|---|---|
| **교사** (초등학교 담임) — 주 사용자 | 학부모 메시지를 받는다. 걸러진 요청 요약을 보고 답장한다. |
| **학부모** | 담임에게 메시지를 보낸다. 거친 표현을 쓰면 보내기 전에 경고를 받는다. |
| **관리자** (교감·민원대응팀) | 위협 메시지를 넘겨받아 학교 차원에서 대응한다. |

## 2. 문제 상황

교사는 공격적 메세지속 요청을 이해하기위해 메세지를 읽으면 모욕적,공격적 메세지 또한 읽어야하며
이것이 쌓여 직무 스트레스,교권 침해로 이어지기도 한다.

## 3. 원인

1.학교 통합 플랫폼은 있지만 필터링 장치가 없다.
   2026년 3월떄부터 학부모 연락이 학교 공식 플랫폼으로 모이는 서비스가 사용되지만,플랫폼에 모인 메세지는 그대로 교사에게 가기에 있으나 마나하는 앱

2.기존 앱은 다 막거나,다 받거나 둘중 하나
   메세지 OFF 기능을 키면 일반 학부모의 요청도 막히고,끄면 민원 공격을 받을수도 있음

3.위협적인 메세지를 받아도 일을 키우고싶지않아 교사 혼자 감당
   협박,공격적 메세지가 와도 학교 대응 체계로 보고하기도 애매해 쉬쉬하는 분위기다.

4.보내는 쪽에 공격적 표현을 보내기전 멈출 계기가 없음
   순간적 흥분으로 공격적 표현을 쓰는 것 또한 잘못이지만 이를 막거나 한번 생각해볼 기회조차 없음


## 4. 해결 방안

원인 하나에 해결책 하나씩 대응한다.

| 원인 | 해결 방안 |
|---|---|
| 1. 걸러 주는 장치가 없다 | **AI 완충:** AI가 메시지를 먼저 읽고, 공격 표현을 가린 뒤 **요청 요약**만 교사에게 보여 준다. |
| 2. 다 막거나 다 받거나 | **내용은 그대로, 표현만 거름:** 요청은 하나도 빼지 않는다. 교사는 원하면 [원문 보기]로 언제든 원문을 볼 수 있다. |
| 3. 위협을 혼자 감당한다 | **위협 자동 이관:** 위협 메시지는 관리자에게 자동으로 넘기고, 원문을 시간과 함께 보존한다. |
| 4. 보내는 쪽에 멈출 계기가 없다 | **보내기 전 경고:** 학부모가 거친 표현을 쓰면 "이 표현은 교권 침해로 기록될 수 있어요"라고 알리고 순한 문장을 제안한다. |

추가적으로 꼭 있어야 하는 기능
- 긴급 메세지(학교폭력,아동학대,안전 관련)은 원문 그대로 맨위에 보여주기
- 애매한 공격적 표현은 위협으로 선정하기,놓치는 것보다는 좋음
- 단체 톡방을 만드는 과정에서 카톡등 개인 메신저가 노출될수 있기에 단체 톡방 기능 추가

## 5. 기대 효과

| 누구에게 | 효과 |
|---|---|
| **교사** | 공격적 표현에 노출되지 않고 학부모의 원하는 의도만 보고 일하기|
| **학부모** | 원하는 의도는 전달되고,보내기전 표현을 돌아볼 기회를 얻음 |
| **학교** | 교사에 대한 위협이 교사 개인에 대한 위협이 아닌 학교 자체의 공격으로 보고 학교 대응 체계로 넘어옴 |
